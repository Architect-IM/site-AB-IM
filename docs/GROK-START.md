# Подключение Михаила через браузерный Grok Build

Работаем с одним сайтом в `sites/irina-architecture` репозитория https://github.com/Architect-IM/site-AB-IM.

GitHub уже предоставляет `lunkinmihail-hub` право записи. Подключение аккаунта GitHub в Grok и возможность отправлять выбранную ветку проверяются со стороны Михаила. Кнопка экспорта проекта сама по себе не доказывает, что Build умеет получать обратные изменения из GitHub.

## Первое сообщение в Grok

Скопируйте в свой чат Build:

> Мы с Ириной совместно редактируем сайт в https://github.com/Architect-IM/site-AB-IM. Мой GitHub — lunkinmihail-hub, у него есть права записи.
>
> Сначала проверь доступ к этому репозиторию и возможность получать изменения и отправлять отдельную ветку через доступное подключение GitHub. Прочитай актуальные AGENTS.project.md, docs/COLLABORATION.md и sites/irina-architecture/AGENTS.md из main.
>
> Получи свежую main и подготовь мою ветку mihail/work, сохранив существующие изменения, если они есть. Общая кодовая база находится только в sites/irina-architecture; это приложение Vinext/React, которое уже работает в Sites. Старый TanStack-сайт в корневом src — прежняя версия.
>
> Проверь запуск общего приложения. Для встроенного просмотра Build используй порт 8080 и адрес 0.0.0.0; запускай пакет из sites/irina-architecture. Пакетный менеджер pnpm 11.25.0, Node.js не ниже 22.13. Сохрани рабочие механизмы своей платформы, необходимые для предпросмотра.
>
> Для каждой задачи используй ветку mihail/название-задачи от свежей main, проверяй typecheck и build, отправляй изменения в GitHub и открывай PR в main. Основной сайт в Sites не публикуй. После отправки дай ссылку на PR и его предпросмотр GitHub Pages.
>
> Если в моём режиме Build недоступны импорт репозитория, выбранная ветка, GitHub-запись или запуск этого приложения, скажи точно, на каком шаге это выяснилось. Не создавай новую реализацию и не заменяй содержимое репозитория полным экспортом старого проекта.

## Техническая памятка для помощника

В чистой копии репозитория:

```sh
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c mihail/название-задачи
cd sites/irina-architecture
corepack pnpm install --frozen-lockfile
corepack pnpm dev --hostname 0.0.0.0 --port 8080
```

Если ветка уже существует, переключиться на неё и аккуратно объединить свежую `origin/main`. Не выполнять принудительный сброс пользовательских правок. Если Corepack отсутствует, использовать установленный pnpm указанной версии.

Перед отправкой:

```sh
corepack pnpm typecheck
corepack pnpm build
```

Эта инструкция не создаёт подключение внутри чужого аккаунта Grok. Первое успешное получение `main`, запуск общего приложения и отправка своей ветки подтверждают совместимость и доступ. Пока эти шаги не проверены, GitHub-часть готова, а подключение Grok остаётся незавершённым.
